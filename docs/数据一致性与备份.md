# 数据一致性与备份

## 删除与重试

主库删除资料/分块、同步图谱证据和登记内容清理任务，在同一事务中提交。
随后清理原文库、分块库与受管原文件。失败时资料已不能参与检索，响应中的 `cleanup_pending` 为 true，页面会明确提示；不会把部分成功当作完全失败要求用户重复删除。

待处理任务保存在 `content_cleanup_jobs`，记录尝试次数及错误码。应用重启自动重试最多 100 条；管理员也可以调用：

- `GET /api/v1/data/cleanup-jobs` 查看待处理任务。
- `POST /api/v1/data/cleanup-jobs/retry` 重试最多 100 条。

原文件只允许在配置的 storage_path 内清理；已被重新导入资料引用的文件保留。清理操作幂等，不重复清除其他块仍然支撑的实体关系。

这属于持久化补偿机制，不是假称三个 SQLite 文件具有一个跨库原子事务。内容库长期被占用时，必须先解除占用再重试。

## 备份与恢复

在项目根目录执行（目标备份目录必须不存在）：

```powershell
python -m scripts.backup_databases --backup-to .runtime/backups/my-backup
python -m scripts.backup_databases --verify .runtime/backups/my-backup
python -m scripts.backup_databases --restore-from .runtime/backups/my-backup --restore-to .runtime/my-recovery
```

备份按主库、原文库、分块库顺序取得 SQLite 写锁，复制稳定快照，校验完整性、外键、文档/分块对应及 SHA-256。短暂阻止写入，但不关闭服务。锁无法及时取得则失败，不输出有效备份清单。

恢复只能写入新目录，原件从备份 BLOB 重建，并更新恢复库中的原文件路径；待清理任务不能触碰原线上目录。恢复完成并不自动切换线上服务。实际切换前应先停止服务，把三个数据库路径和 storage_path 指向恢复目录，再启动验证。

备份含完整业务资料和加密后的设置，不含 `.env`、环境 API Key 或 ngrok 配置。Windows DPAPI 加密值需要原 Windows 用户环境解密；便携密钥应另行安全保管。备份仍是敏感资料，不能放到公共下载目录。
