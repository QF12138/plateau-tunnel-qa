# 设置与执行一致性

2026-09-29 修订：

- 问答 `response_mode` 只允许 `brief`、`detailed`；省略时使用后台已保存默认值。
- DeepSeek、兼容 API、本地 Ollama 均收到实际回答要求；内置摘录降级也区分简要与详细，并保留限制提示。
- 正常生成审计的 retrieval_parameters 记录实际 response_mode。
- 简要模式是篇幅指导，不是截断器；冲突、适用条件、安全说明优先于长度。
- 文档入库标注“切块策略：结构化字符切块（本地）”。大小和 overlap 实际控制切块，不声称由回答大模型语义切块。
- 旧请求 `same_as_answer` 保持接收兼容，但实际策略记录为 `structural-v1`；未知策略拒绝，新资料不会记录虚假的模型执行结果。旧资料元数据不改写。
- 审计及高风险复核提示一直实际启用，现在界面明确固定启用，API 拒绝保存关闭状态。

实际 DeepSeek 验证（测试会生成两条正常审计记录）：同一问题简要回答 450 字、详细回答 1388 字，两者均有 8 条引用。此验证确认模式传递及真实生成，不等同于逐段事实正确性评估；引用逐段校验仍在后续模块计划中。

全量回归 100 项通过；mypy 检查 57 个源文件无错误；页面内联 JavaScript 语法通过。浏览器确认切块方式说明可见、安全开关不可误关闭。仅存在已有 Starlette/httpx 弃用警告。
